# 《镇长不在的时候》玩法说明

> 面向「第一次打开这个仓库、不知道该怎么玩」的人。
> 本文所有数字都对着当前代码（`scripts/game/**`、`scripts/player.gd`、`scripts/guard.gd`、
> `data/*.json`）核对过，不是设计稿上的意向值。
>
> 版本对应：`feature/p1-vertical-slice` @ `92af97e`。

---

## 0. 一句话

镇长今晚不在，2–6 个夜里睡不着的人偷偷溜进广场，趁着看门的**老陈**打盹，
把手上的「捣蛋清单」一条条做完，做完就收工回家。

你是捣蛋的那个，**老陈是抓你的那个**。被抓不会扣任何东西，只是被抓的那一条要重做。

---

## 1. 先把游戏跑起来

### 1.1 独立窗口（推荐）

```powershell
cd D:\GodotProjects\after-hours
powershell -ExecutionPolicy Bypass -NoProfile -File tools\run_game.ps1
```

这个脚本起一个**独立进程**的普通 Godot 窗口（不走编辑器的 F5）。
实测：编辑器 F5 起的嵌入式窗口键盘事件**不可靠地转发**给游戏（第一个键有效、
后面的键全丢，表现为「走几步就动不了了」）；独立进程 8 个键里 7 个正常。

### 1.2 进对局后，先用鼠标点一下窗口

**Godot 窗口默认不抢键盘焦点**。进对局后如果按方向键没反应，先在窗口里
**点一下鼠标**，再按方向键。

### 1.3 单机（一个人玩）

1. 大厅点 **「创建房间」** → 状态栏变成「已创建房间，等待朋友加入…」
2. 点 **「开始这一夜」** → 进对局

**不要先点「加入房间」**：单机没有房主，加入会在 8 秒后超时并退回大厅
（状态栏会写明「连接超时：没连上服务器，已回到大厅」）。
现在「加入房间 → 创建房间」这个顺序也不会再把房间拆掉了，但没有任何意义。

### 1.4 双窗口联机（本机）

端口固定 `28000`，地址固定 `127.0.0.1`。

1. 窗口 A：`run_game.ps1` → 点「创建房间」
2. 窗口 B：`run_game.ps1 -Second` → 点「加入房间」
3. 两边都就位后，**窗口 A** 点「开始这一夜」

两端都会自动切进对局场景，不用手动切。

## 2. 对局里怎么操作

| 操作 | 按键 |
|---|---|
| 移动 | **方向键**（← ↑ → ↓）。当前只绑了方向键，**WASD 不生效** |
| 捣蛋 | **按住** `E` |
| 收工 | 右下角「收工」按钮（**只有房主能点**） |

- 角色速度 150 px/秒（约 4.7 格/秒，1 格 = 32 px）。
- 镜头跟着你的角色走，你永远在画面正中。
- 左上角是**你自己那一份**捣蛋清单（每行一个 `□ 标题`）。
- 右上角那行字是操作提示 + 「已完成 N 条」。
- 被抓时**屏幕上方中央**会弹一条吐槽气泡（「我的萝卜呢？！」），2.5 秒后消失。
  它不跟着你的角色走，是固定位置的提示条。

## 3. 捣蛋清单（你的任务）

### 3.1 怎么拿到牌

开局时房主给**每个人**发一份清单。牌数按人数定：

| 人数 | 每人牌数 |
|---|---|
| 1–2 人 | 3 张 |
| 3 人 | 4 张 |
| 4–6 人 | 5 张 |

发牌还遵守三条：

- 池子里只留**这一局地图上真实存在**的道具对应的行为；
- 同一类（偷 / 乱 / 恶作剧 / 布置 / 动静）不超过 2 张；
- 至少 1 张「动静/布置」类 + 至少 1 张「恶作剧」类；
- **不同玩家的清单组合互不相同**（按行为集合算，不看顺序）。

同一个行为**可以**同时发给多个人（10 种行为撑不起 6 人互不重复）。

### 3.2 怎么完成一条

1. 走到目标道具旁边 **40 px 以内**（约 1.25 格）；
2. **按住 `E`**，进度条按这张牌的耗时累积；
3. 进度满 → 提交给房主裁决 → **右上角「已完成 N 条」+1**。

> ⚠️ 左上角那份清单**不会打勾**：它只是你手上那几条的文字列表（每行一个 `□`），
> 做没做完全看不出来，只有右上角那个计数会动。

耗时表（`data/mischief.json`）：

| 行为 | 目标道具 | 基础耗时 | 需要搭档 |
|---|---|---|---|
| 偷走杂货铺的萝卜 | 萝卜 | 1.5 s | 否 |
| 偷走镇长的帽子 | 帽子 | 1.5 s | 否 |
| 偷走酒馆的篮子 | 篮子 | 1.5 s | 否 |
| 把广场椅子堆成塔 | 椅子 | 3.0 s | **是** |
| 打翻广场的木桶 | 木桶 | 1.0 s | 否 |
| 拔掉街上的路灯 | 路灯 | 2.0 s | 否 |
| 把长椅搬到池塘边看日落 | 长椅 | 3.0 s | **是** |
| 给花盆穿上外套 | 花盆 | 2.0 s | 否 |
| 把告示牌倒过来 | 告示牌 | 1.0 s | 否 |
| 敲响酒馆的锅 | 花盆 | 0.5 s | 否 |

**搭档**：需要搭档的牌，场上 64 px 内有**另一个玩家**站在同一个目标旁边就算有搭档。
没有搭档**不会失败**，只是耗时 ×2（3 s → 6 s）。

**抢同一个目标**：同一个道具只能被一个人「占住」，**先到先得**。
后到的落败 —— 落败不扣分、不掉进度，只是这一条白做（零失败惩罚）。

## 4. 老陈（守卫）怎么抓你

老陈是全场唯一的守卫，岗位在**告示牌**那一格，世界坐标 (480, 288)。

| 参数 | 值 |
|---|---|
| 巡逻半径 | 120 px（绕着岗位转圈） |
| 移动速度 | 70 px/秒 |
| 视野距离 | 96 px |
| 视野张角 | 80°（正前方 ±40°） |
| 抓捕半径 | 24 px（约 0.75 格） |
| 听觉半径 | 128 px（**当前版本没接上**，见第 6 节） |

行为逻辑：

- **巡逻**：沿岗位周围的圆弧慢慢转，走向哪边就朝哪边看。
- **看见你**（在视野锥里）→ 立刻**追击**。
- **追上**（距离 ≤ 24 px）→ 抓你。
- **跟丢了**（看不见你、怀疑度衰减到 0）→ 先退回「起疑」，再回巡逻。

### 4.1 拔路灯是真的有用的

「拔掉街上的路灯」完成后，那盏灯会真的熄灭。**每盏熄灭的灯**在守卫 160 px 范围内，
让他的视野乘 **0.6**：

| 附近熄灭的灯数 | 视野系数 | 实际视野距离 |
|---|---|---|
| 0 | ×1.00 | 96 px |
| 1 | ×0.60 | 57.6 px |
| 2 | ×0.36 | 34.6 px |

**但要注意「附近」是按老陈当前位置算的 160 px 圈**，而他是在岗位周围转圈巡逻的。
三盏灯离岗位的距离分别是 244 / 187 / 163 px —— 都比 160 略远或更远：

| 路灯 | 到岗位 | 巡逻时最近 | 什么时候算数 |
|---|---|---|---|
| (256, 192) | 243.7 px | 123.7 px | 老陈转到西边时 |
| (640, 192) | 186.6 px | 66.6 px | 老陈转到东北时 |
| (448, 448) | 163.2 px | 43.2 px | 老陈转到南边时 |

也就是说：**灯灭不灭是一回事，老陈此刻站在哪儿是另一回事**。
典型情况只吃到 1 盏（视野 96 → 57.6 px）；
他转到两盏灯中间时可能同时吃到 2 盏（→ 34.6 px，基本等于瞎了）。

地图上总共只有 3 盏灯，全拔掉是有意义的 —— 但要配合「把他引到灯附近」才划算。

### 4.2 被抓了会怎样

被抓 → 你**不能动**，自己慢慢走回自己的出生点 → 老陈回岗位 → 继续巡逻。

**零失败惩罚**（这是这个项目的硬约束）：

- 已经做完的捣蛋**不清零**；
- 手上**正在做的那一条**作废（要重做）；
- 不扣分、不掉命、不淘汰、没有名次；
- 结算页只陈列信息，没有排名。

## 6. 当前版本的已知限制（诚实清单）

这一节很重要 —— 画面上很多地方「看不懂」不是 bug，而是 P1 的范围。

### 6.1 美术是 AI 生成的手绘绘本风（不是手绘精修）

地图、角色、道具全部换成了 **AI 生成的手绘绘本风素材**（不是手绘精修，也不是占位图）：

- 角色 7 张（6 个村民 + 1 个老陈），道具 10 种各自一张，地面是一张 960×576 的
  **整图**（草地 + 手绘土路 + 边缘压暗，由 `tools/bake_map_ground.py` 离线烘焙）。
- 道具现在**外形可辨认**：萝卜、帽子、篮子、椅子、木桶、路灯、长椅、花盆、告示牌、小狗。
- 夜里是**蓝紫夜色**（`CanvasModulate`），每盏路灯有**真的暖光池**（`PointLight2D`）。
  拔掉路灯后光池消失、灯本身压暗 —— 和守卫视野变小是**同一个状态源**（`Interaction.is_lamp_on()`）。
- 角色和守卫都会**随朝向左右翻转**（只改 `flip_h`，节点 `rotation` 恒为 0，人物不会翻倒）。
- 素材按 **2x 出图**（角色 128×128，世界 64×64），`Sprite2D.scale = 0.5` 回到世界尺寸；
  道具按**自然尺寸**出图。两种都用 `offset = (-w/2, -h)` 自动锚定 → 水平居中、底边贴地。

仍然**没有**的东西（还是 P1 范围）：建筑、场景、界面素材、NPC 对话立绘。

### 6.2 玩法上的空缺

- **「敲响酒馆的锅」目前不会真的发出声音**：守卫感知里的 `noise_active` 字段写死为 `false`，
  听觉这一路还没接上。所以这张牌只是个「0.5 秒做完的小任务」，不会惊动老陈。
- **HUD 没有目标指示**：不告诉你「该往哪走」，也没有高亮当前目标；左上角清单只给文字标题。
- **WASD 没绑**：移动只认方向键（`ui_left/right/up/down` 在 `project.godot` 里没有 `[input]` 段，
  引擎默认只给方向键）。按 WASD 不会有任何反应。
- **清单区占左侧比较宽**（210 px 宽的固定面板，视口才 640 px）。
- **远端玩家的化身不会左右翻转**：翻转靠本机的水平速度判定，而远端化身只同步位置、
  没有速度 —— 所以别人的角色永远朝右（本地玩家自己的角色是好的）。
- **只有房主能开局、只有房主能收工**；客户端的「开始这一夜」按钮是灰的。

### 6.3 已知遗留缺陷（还没修）

- **「创建房间 → 再点加入房间」会把服务端 peer 换成客户端 peer**（顺序陷阱）。
  反过来（加入 → 创建）现在是对的。
- 地图边界、HUD 版式、道具辨识度都属于 P2 的活。

## 7. 结算页

房主点右下角「收工」→ 整局结束，所有人切到结算页。每个人一张卡片：

```
玩家 1
捣蛋 3 次    被抓 1 次
· 偷走杂货铺的萝卜
· 拔掉街上的路灯
· 把告示牌倒过来
```

只有信息陈列：**没有名次、没有分数、没有胜负**（零失败惩罚）。
「捣蛋 N 次」是成功完成的条数，「被抓 N 次」是这一局被抓了几回。

## 8. 术语对照

| 说法 | 代码里的名字 | 含义 |
|---|---|---|
| 捣蛋清单 | `hand` / `deal` | 每人这一局的 3–5 张任务卡 |
| 捣蛋行为 | `Mischief` | 一条可做的坏事（`data/mischief.json`） |
| 目标 | `target_tag` | 这条行为要作用在哪种道具上 |
| 搭档 | `has_partner` | 同一目标旁 64 px 内的另一个玩家 |
| 归属 | `ClaimLedger` | 房主侧的「先到先得」台账 |
| 押送 | `escorted` | 被抓后走回出生点的状态 |
| 收工 | `end_round` | 房主结束这一局 → 结算页 |
